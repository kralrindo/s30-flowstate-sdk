# 18. S30 playlist schedules for the S30 client's lobby (2026-10-26)

The S30 lobby UI (`ui/dialogs/panel_gamemode_select_public.nut` #775) failed with "No map for given playlist
'-ranked-0'". This doc covers why, and the dedi playlist file that fixes it. IDA work used copies in
`analysis/idb/fork_playlists` (the S30 IDB, plus a raw `r5apex_ds.exe` decompiled function by function).

## How the S30 client gets its playlists
- **Startup:** it loads `playlists_r5.txt` itself: `0x3D9AA0`, `-playlistFile` overrides it, and the copy shipped
  in `startup.rpak` is a `wrap` asset. It reads a local `playlists_r5_patch.txt` only with `-localPatchPlaylists`
  (`0x3DE440`).
- **Connected:** `svc_Playlists` (S30 15) → handler `0x3F5CF0` → `0x3D9880("SVC_Playlists")`, which parses the
  received text with `0x3D7210` and **replaces** the client's playlist data with it.
- **Patch marker:** `0x3D7210` looks for `@@@@ -<[PaTcH]>- @@@@` in the raw text (`strstr`, before any parsing),
  parses the text before it as the base and the text after it as a patch, then merges them (`0x5E0F20`, mode 4).
  The base's `patchVersion` must be empty or equal to the patch's (neither file has one).
- **What the dedi sends:** its raw playlist file text. S3 `SendServerInfo` `0x304BE0` copies the buffer that the
  playlist reader `0x277A20` filled; this is the SDK's `g_ppPlaylistFileText`, which it splices for mods.

## Why the schedule names were empty
- **The S30 parser** (`RecursiveLoadFromBuffer` `0x5DFA10`) renames a key/value pair that is followed by `{`
  to `"key value"` and keeps the value. So `PlaylistSchedule ranked { … }` becomes the node
  `PlaylistSchedule ranked` with value `ranked`.
- **Rotation and schedule names are that value:** the schedule parser `0x3D64C0` and the rotation parser
  `0x3D60C0` take it from `GetString(node, NULL)`.
- **The dedi's blocks had no value:** it wrote them quoted (`"PlaylistSchedule ranked"`), so the schedule's name
  was `""`.
- **That broke the names:** with the convar `playlist_use_decorated_names` 1 (`0x716C0`), entries are named
  `"%s-%.*s-%zu"` (schedule, entry, index), so the empty name gave `-ranked-0`. The lookup `0x3D8F60` splits a
  decorated name at `-` and uses the middle segment as the playlist name. Here the empty first segment was
  dropped, so that segment was `0`, which is not a playlist.
- **The dedi also lacks the target playlists:** apart from the naming, its schedules point at playlists it doesn't
  have.

## Can the S3 dedi read S30's syntax? No
- **Stock Valve parser:** `r5apex_ds` `0x475DC0` / `0x4765E0` reads `PlaylistSchedule ranked {` as the pair
  (`PlaylistSchedule`, `ranked`), then a key named `{`. It fails with "got } in key".
- **Never used:** the S3 exe contains no `PlaylistSchedule`, `PlaylistRotation` or `PaTcH` strings.
- **Errors are not fatal:** every top-level key is parsed as a root peer and errors are only logged
  (`0x472C70` → `0x43C980`).

## The file
Generated by `s30/tools/dedi_playlists_s30.py <dedi playlists_r5_patch.txt> <S30 playlists_r5.txt> <out>`, with the
reader `s30/tools/playlist_kv.py`. The S30 input is the `startup.rpak` wrap, exported by RSX to
`asset_pipeline/playlists_s30/export/wrap/playlists_r5.txt`.

1. **Base:** the dedi file without its 14 quoted `PlaylistRotation` / `PlaylistSchedule` blocks. S3 never reads
   them, and S30 cannot name them.
2. **Marker:** `// @@@@ -<[PaTcH]>- @@@@`. S3 sees a comment; S30 splits the text there.
3. **Patch:** a second `playlists` root with:
   - S30's 8 rotations and 10 schedules, verbatim.
   - The 30 S30 playlists those name that the dedi lacks, including their inherit parents.
   - The 3 gamemodes those use that the dedi lacks (`gungame`, `survival_br`, `tdm`).
   - Nothing that already exists in the dedi file is overridden, so its modes and vars stay as they are on the
     client too.

Gates (the generator refuses to write if one fails):
- **S30 view:** emulates the client (split, then merge per `0x5E0F20` mode 4). Every rotation and schedule must
  have a name. The lobby's schedules (ranked, regular_1, regular_2, ltm, mixtape, training, firing_range) must
  exist. Every schedule and rotation target must resolve, and every added playlist's inherit chain and gamemodes
  must resolve.
- **S3 view:** emulates the dedi's reader. Its first `playlists` root must equal today's file minus only the
  removed blocks. Result: equal. The S30 root adds 58 logged KeyValues errors and 9 unused root peers.

Staged at `asset_pipeline/playlists_s30/platform/playlists_r5_patch.txt`. The install script refuses while the
workspace dedi runs, keeps `.s21` and `.pre_playlists_s30`, and copies the file to both the dedi and the client,
as before:

    pwsh -File F:\apex_builds\m2299605425033557595\asset_pipeline\playlists_s30\install.ps1

## Test
Start the dedi with `+map mp_lobby` and check it reaches `ready`. Its log will show `KeyValues Error` lines from
the S30 patch root; its own modes are unchanged. Then connect the S30 client: the game-mode panel should list
modes without the `-ranked-0` error.

## Open risks
- **Not run yet:** the 58 KeyValues error lines on the dedi are expected but haven't been seen in a real run.
  They could be avoided with a server.dll change: in `Playlists_Parse` (`rtech/playlists/playlists.cpp`), parse
  only the text before the marker and keep the full text in `g_ppPlaylistFileText` for `svc_Playlists`.
- **SDK mod-splice scanner:** `Playlists_SpliceModPatches` (`CPlaylistTextScanner`) may not parse the S30 patch
  root and would then log "base playlist text did not parse; mod patches not merged". It returns without changing
  the text. No dedi mods are loaded today.
- **Unused root peers:** the extra root peers are attached to the root KV's peer chain. The S3 engine's playlist
  code uses the first root (`0x277C50`); a consumer that walks root peers was not looked for.
- **Ranked dates:** S30's ranked lock and end-date default vars aren't added. The UI treats them as missing (no
  lock, `ornull`).
- **Selecting a mode:** picking an S30-only playlist in the lobby does nothing useful (no matchmaking service).
  This only fixes the UI's lookups.
