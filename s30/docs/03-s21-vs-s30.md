# 3. S21 vs S30: differences and compatibility matrix

Evidence:
- `s30/tools/pattern_census.py` runs all 1,818 SDK signatures against S21 DX11, S21 DX12, the S3 dedi and S30.
  Data: `s30/status/census.json`.
- `s30/tools/strings_diff.py` diffs strings between S21 DX12 and S30. Output: `analysis/strings/`.

## Headline numbers

| measure | S21 | S30 | result |
|---|---:|---:|---|
| SDK signatures unique on the S21 client | 760 | 282 unique, 31 multiple, 447 missing | **37.1 % resolve unchanged** (unverified) |
| net bridge symbol table (`net_bridge_addrs.cpp`) | 218 signatures | 91 unique, 19 multiple, 108 missing | key data symbols missing: RecvTableListBase, ClientClassArray/Count, NetChan, NetTime, EntityHandleTable |
| `.text` size | 0x12F958C | 0x148DFAC | +8 % code |
| RTTI type names | 1,089 | 0 | S30 is stripped, so classes must be identified from code |
| `svc_`/`net_` string family | 90 | 83 (82 shared) | net convars nearly identical; DTLS encryption convars exist in both |
| convar-like strings | 795 | 859 (729 shared) | S30 adds `net_protocol_use_script_md5/_rpak`, `cl_strict_transport_checks`, `script_net_data_global*`, `sv_script_compile_during_map_load`; drops `cl_clock_correction` |
| script-native-like names | 5,527 | 6,186 (5,380 shared) | about 150 S21 names gone, about 800 new; exact native tables still to dump (B3) |
| launch params | 270 | 284 | `-forceSendTable`, `-noorigin`, `-dev`, `+playlistFile` still present; S30 adds `-insecure`, `-run_headless`, `-waitfordebuggertoattach` |
| RPak container | v8 | v8 | same container; asset versions differ: mdl_ v20, aseq v14, arig v7, asqd v1, BSP v51 (s30-port-kit) |
| script paks | none (loose files) | `script_client(01).rpak`, `script_ui(01).rpak` | S30 ships compiled script trees in paks; the loose-file path strings are still present |

## Compatibility matrix

States: **C** compatible · **P** partially compatible · **I** incompatible · **N** not yet investigated.

| # | component | state | evidence / reason | where the fix goes |
|---|---|---|---|---|
| 1 | Injection (import-table `.l2` loader) | P | Same technique works on any PE; S30 imports differ (`dbghelp`, `AVRT`, `ntdll`). Untested whether S30 checks its own import table or image. | patch a copy of the S30 exe; loader keyed on TimeDateStamp |
| 2 | Loader product selection | I | Selects by exe name; S30 and S21 DX12 share `r5apex_dx12.exe` | loader: select by image identity |
| 3 | tier0/tier1/convar/cmd | P | engine 58 %, `public/tier1` 67 %; ConVar layout unverified | re-sign, verify layouts (0x98 vs 0xA0 dual ABI) |
| 4 | Filesystem/VPK | P | `FullFileSystemPtr` resolves, `FileSystemStdioInstance` ambiguous; S30 has no `vpk\` | verify |
| 5 | RPak loader hooks (`rtech/pak`) | P | 40 % resolve; `PakFindAsset`, `PakRequestLoadByName` missing | re-sign |
| 6 | Origin/EA/EOS offline | I | `OriginInitFatalCall`, `PatchSite_EosLauncherGate`, `PlatState` missing; S30 adds EOS SDK paths | new stubs + loopback-only network guard |
| 7 | Integrity checks (`sys_integrity`) | N | `IntegrityEnable` missing on S30 | B6 |
| 8 | Netchannel framing (seq/ack/flags, nonce, splits) | N | bridge reimplements the S3 side; the S30 side's own framing must be confirmed | runtime trace |
| 9 | Net message ID map (S3→client) | I | the S21 IDs were renumbered against S3; S30 numbering is unknown, no RTTI | B1: dump msgArray at runtime + GetType/RFB matching |
| 10 | Message body formats | N | each FORMAT BRIDGE entry must be rechecked against S30 ReadFromBuffer | per message |
| 11 | Snapshot / entity decode | P | `TransitionEntity`, `PropApplyLoop`, `RecvDecode` resolve; `ParseDeltaHeader`, `CopyNewEntity`, `SnapshotProcess` missing | re-sign + verify |
| 12 | SendTable transmit path | P | `-forceSendTable` and `sv_allowSendTableTransmitToClients` exist in S30; recv-table registry symbols missing | re-sign |
| 13 | Entity classes / recvprops | N | S30 adds and removes props; dedi dt_extend publishes the S21 set | B2, then the dedi |
| 14 | Prediction / usercmd (C2S) | N | `PlayerRunCmdPred`, `ClWriteMoveCmds` resolve; usercmd layout unknown | verify |
| 15 | Clock/drift | I | `cl_clock_correction` removed in S30; `ClockDrift` missing | re-derive |
| 16 | String tables, persistence (pdef) | P | most pdef symbols resolve | verify |
| 17 | Script VM (`vscript`) | P | 22–32 % resolve | re-sign |
| 18 | Flowstate client/UI scripts on S30 natives | N | about 150 S21 natives gone, S30 compiles from script rpaks; RUI/menu assets differ | B3 (largest risk) |
| 19 | Script remote functions / netvars | N | S30 adds `script_net_data_global*` and the `net_protocol_use_script_md5/rpak` protocol checks | B3/B5 |
| 20 | Playlists | N | `PlaylistRulesLoader` resolves; S30 playlist schema unknown | B5 |
| 21 | Renderer / D3D hooks (`windows`, `materialsystem`) | P | `windows` 7 %, materialsystem 40 %; S30 is DX12-only, the D3D11 paths are dead | port only what is needed |
| 22 | Dedi (server.dll) | C | unchanged binary; keeps working with S21 | S30 profile later for dt_extend |
| 23 | Server assets for S21-era maps | P | 5 S30 map names exist on the dedi, but built from S21 BSPs | E1 |
| 24 | S30-only server assets | I | mdl_ v20, aseq v14, BSP v51 need conversion | rmdlconv / R5-AnimConv `-i 30 -o 3` / bspconv `-dedi` (proven by s30-port-kit) |
| 25 | Flowstate client paks (`common_flowstate`, `effects_sdk`) on S30 | N | built with S21 asset versions; the S30 loader may reject old versions | test, then rebuild |
